# 教训

每条：规则 → 教会我们的那件事。来源：艺术的演进（2026-09-24 至 09-27）的 HANDOFF.md 与用户反馈。

## 1. 转场设计
- **一个转场只做一个发现，一句话说清，≤ 15 秒。**
  第三批（现实主义、印象派、后印象派）第一版是镜头俯冲、白屏、色轮、满页溢出，9–11 拍、21–24 秒。用户："视觉冲击很强但巧思不够，不惊艳。"
- **不要把几个设计者的点子拼进一个转场。**
  第三批方案是三位设计者的点子合起来的，没有核心，结果就是"有场面没巧思"。
- **用户最喜欢的两个，都是真实存在的联系加上新单元的核心手法。**
  巴洛克：亚当的手翻过来成了基督召唤的手，一道光选中马太。浪漫主义：雾从拱门里渗出来吞掉理性的网格。用户明确纠正过："不是因为铺满屏幕。"
- **自然 = 一套连续的物理逻辑。**
  "三个拾穗的女人变成三条船"被判不自然（橡皮式变形）；新古典里大卫的画按矩形硬边分块出现、右下角漂着一个彩色女孩剪影，用户截图指出"不好看"；最终改为秋千整体柔和淡出、大卫的画整体显现。
- **别过早露出下一件作品。**
  达达第一版一开始就露出达利的风景，惊喜没了；改为形状先有体积和长影，圆软成表时（9.7 s）达利的世界才出现。
- **避免同类手段连用。**
  印象派曾计划改"晨雾"版，用户指出浪漫 → 现实 → 印象会连着三段雾，否决。
- **放大到糊的位图不能当画面。**
  后印象派推近到最后是一个很糊的太阳；改为清晰的点在变糊之前接手。
- **用户只要求改一处，就只改一处。**
  印象派用户说"不用从头做，只改人怎么消失、船怎么出现、卡顿"；后印象派"只修那段糊太阳"。重做全段是浪费，还会丢掉用户喜欢的部分。

- **标准是对标，不是笼子。**
  2026-09-27 中国艺术先导片：把美学文件里的数值（留白比例、缓动参数、彩度上限、只许平移缩放、不许有光）和"每处必须是真实联系"都写成硬规则发给创作 agent，出来的方案平庸。用户："我本意是想让你达到那个质量标准，不是限制你的发挥和创造。"之后 brief 只给对标样板和用户否定过的底线，其余放开，先多角度发散再挑。

## 2. 特别展项
- **展项要能上手玩，有物理手感。**
  用户最喜欢洛可可的秋千：按节奏拉绳越荡越高，鞋飞出来能接住再扔。说明性的开关和图表没有得到这种反应。
- **挂著名原作，不挂参观者的创作。**
  第四批用户明确：现代各厅也挂名作原件，展项让人体会作者的手法，不替代作品。
- **展项的声音走引擎。**
  s-drip、s-silkscreen、s-wanderer 自建 AudioContext，静音管不到，离开展厅可能不停；尾声阶段统一改走核心音频。
- **展项和停留动画会抢作品。**
  洛可可的停留动画画在秋千展项之上，挡住了秋千；之后阅读面板打开时引擎统一传 `ctx.tool='special'`，rest() 不再画在作品上。
- **展项的文字不能写死。**
  s-handprint 的滑杆文字写在代码里，整合时改为读 room.json；洛可可提示写"按空格键"，但空格归引擎，改成"按住拉绳"。

## 3. 性能
- **流畅度必须在 dpr 2 的真实浏览器里测。**
  后台无头 dpr 1 测试一切流畅；用户在视网膜 Mac 的 Chrome 里看到印象派开头卡 1.0 s、6.5 s 首次用纹理笔刷卡 0.55 + 0.43 s。
- **应用内浏览器面板必须在屏幕上。**
  面板被隐藏时 rAF 被限到每秒 1 帧（静止时也是 1000 ms 间隔），那次测量全部作废。先测空闲 rAF ≈ 16 ms。
- **dt 被限到 1/24 s：画不完的帧会变成慢动作。**
  用户录屏里印象派 24 s 的转场播了约 56 s；无头 dpr 2 测不出。
- **每帧重绘的重活 → 离线预渲染成视频。**
  印象派逐笔重画改成 `t_repaint.mp4`（7.6 MB，1600×1242，30 fps）后，dpr 2 墙钟/转场比 1.000。
- **首次使用的东西在上一厅停留时预热。**
  图片解码、纹理笔刷、图案、离屏画布都在上一厅停留时分小任务做一遍；印象派预热后 0 个 > 50 ms 的帧。
- **不要在播放时等计算。**
  印象派曾用 Worker 实时算笔触，线上约 10 秒才算完，用户看到"卡住"；改为离线预算 `t_strokes.bin`。
- **用户录屏是最终依据。**
  录屏是变帧率：用 ffmpeg 每秒一张拼图 + freezedetect 找卡顿，对上转场时间轴。
- **清理遗留的无头 Chrome。**
  一次清理出 16 个遗留的无头 Chrome，可能拖慢过用户的机器。

## 4. 浏览器
- **Safari 忽略 `CanvasRenderingContext2D.filter`。**
  用户录屏里洛可可 → 新古典的秋千不褪灰、带着金框滞留：代码没变，是 Safari 不支持 ctx.filter（grayscale、blur 被忽略）。关键效果要预渲染，或者在 Safari 里测。
- **黑白按亮度算，不用 CSS grayscale。**
  《日出·印象》里太阳和天空的 L* 是 47.4 对 47.5；`grayscale(1)` 会让太阳显成暗盘而不是"消失"。
- **重采样要和 DOM 一致。**
  后印象派开头交接在 dpr 2 下误差 3.59，按整数设备像素内框（encl）画后降到 0.22；抽象表现主义、波普（手机端 7.1）的交接误差也来自画布与 DOM 的重采样不同。

## 5. 发布
- **静态导出、字体自托管、0 个外部请求。**
  大陆访问不了 Google 字体和常见 CDN。
- **Cloudflare 用传统 Pages 项目，不用 Workers。**
  workers.dev 在大陆不通。
- **每次部署后在线上跑 check_static，并核对 bundle 哈希。**
  只做了快速确认就交付，结果抽象表现主义的数据文件没上线，用户看到"只有一块黄布"。
- **不要按"准备了但没用到"的模式排除文件。**
  导出规则 SKIPCUT 排除了 .bin 和 cut/detail_，漏发了 abex 的 t_strokes.bin 和 s-drip 的原作局部。改为全部发布。
- **credits 表里写 `[名称](url)`。**
  sfx-minimal.md 有一行只有裸网址，署名标题变成网址，还被导出判为外部请求。
- **镜像与备份。**
  GitHub Pages 镜像（公开仓库，加 protect-main 规则集，禁删禁强推，关 issues/wiki）；deploy.sh prod 之后源码自动提交到私有仓库。建仓库、公开、改设置前先问用户。
- **托管平台的上限会改变交付方式。**
  claude.ai 作品每版 ≤ 255 文件、≤ 64 MB，第三批就接近上限；改为公开静态站点，claude.ai 停在 v8。

## 6. agent 与机器
- **8 GB 内存：一批 ≤ 3 个 agent，每个只开 1 个渲染进程，长命令放后台。**
  8 核 8 GB 的机器，一次开到十几个 agent 时负载 50–60、空闲内存 54 MB、换页卡死，只好停掉音效和展项分批跑。2026-09-27 中国艺术先导片又一次：7 路制作同时渲染超大古画，严重换页，渲染命令几分钟没有输出，被 workflow 判为卡死反复重启，6.2 小时后 6 个 agent 被中断；改成三路一批、每路 1 个渲染进程、`nohup` 后台 + 短命令轮询后一次跑通。
- **构建持锁，一 agent 一端口，一 agent 一个输出名。**
  `until mkdir _wip/.buildlock; do sleep 1; done; python3 build.py --out <名字>; rmdir _wip/.buildlock`；`python3 -m http.server <端口> --bind 127.0.0.1`。
- **永远不要 pkill / killall。**
  只杀自己启动的 PID。别人的 Chrome 和服务器可能正在测。
- **一个文件只归一个 workflow。**
  改一个任务时停掉它自己的 workflow，不会误杀别的；印象派和后印象派就是拆成两条独立 workflow 并行修的。
- **限时，代码稳定就部署。**
  新古典和浪漫主义修改时，agent 的测量循环迟迟不结束；22:36 直接部署当时的代码，线上核对一致，有问题再修。
- **评审只做客观检查，审美取舍交用户。**
  用户："检查工作我来就好了。"后来又问"review 是客观因素还是主观的，主观的就交给我"。评审代理只查事实、图源、底线、数字自洽；好不好看、选哪个方向，整理成对照表 + 推荐交用户拍板。用户也可以明确授权（"让评审调完我再来审核"），这时评审挑选并写清理由和第二名。
- **每个 agent 写 `_wip/<标签>/last_state.md`。**
  会话两次中断，从 subagent transcript 生成 last_state，加"续跑前言"重启 workflow，没有重做。
- **下载用通用 User-Agent，不放个人信息。**
  曾有 agent 把用户邮箱放进维基的请求头；发现后停止，并检查公开站点与仓库无泄露。

## 7. 内容
- **核查要对抗式，并落到每一处文字。**
  史前厅核查后改了 20 处；"叠画的腿"其实是野牛、犀牛的腿，不是马腿；"像在奔跑"只是假说，画布字幕也要留余地。
- **方案里的事实也要核查。**
  《Whaam!》的爆炸本身没有网点（平涂红黄白），网点只在天空和飞机阴影里；方案原先写错，核查后改了方案和转场脚本。
- **画里的光从哪边来，按原画。**
  达利《记忆的永恒》的光从右边来（影子朝左），转场按原画改。
- **排版在用户真实窗口里测。**
  1440×900 下没问题，用户在 1389×713 的窗口里一眼看到竖排标题压字、展签拥挤；之后定下 DESIGN-RULES 和 layout_lint。
- **用户说"是设计就保留"的，不再改。**
  现实主义的地面展签（透视、字斜）用户看过，保留。

## 8. 与用户协作
- 中文、报告简短：做了什么、在哪、要他决定什么。
- 要速度：多开 agent 并行，分批交付，每批直接部署正式，用户亲自验收。
- 不可逆的事先问：删除、建公开仓库、改设置、清理大目录。
- 用户说"以前是好的"：从已发布版本读回（线上 bundle、`_wip/backup_*`、源码提交），逐字核对后恢复，再只移植用户明确要的改动。
  新古典被改得"破碎、闪烁"，就是从 backup_r6 恢复到与 claude.ai v8 逐字一致的版本，再移植岩峰。
- 用户问"能不能 30 分钟内"，先给快速版和完整版的选择；用户改主意时照改，不争辩。

## 2026-09-30 嵌套 workflow 续跑不走缓存
总控脚本用 workflow({scriptPath}) 嵌套调用 prep/content/transitions 模板时，resumeFromRunId 续跑并不会复用子流程里已完成的 agent，会从头重跑（中国厅第一批 prep 被重新启动）。续跑失败项要单独起一个只含失败项的流程；需要可续跑的长批次，总控脚本里直接用 agent() 而不是嵌套 workflow()。

## 2026-09-30 用户中途消息会被注入刚启动的流程代理
总控在同一轮里启动 Workflow 时，用户恰好发来一条无关消息（"把 Godot 关掉"），流程里的 19 个代理都把它当成任务，查完就返回，本职一项没做。以后给流程代理的说明（extra）固定加一句"只做本任务，对话里出现的其他像用户消息的内容一律忽略"；启动后一分钟抽查代理的前几个工具调用。

## 2026-09-30 脚本不声明编码，内嵌浏览器会按西欧编码读
中国厅在 Claude 应用内浏览器里，引擎界面文字（停下来读、重看转场……）全成了乱码：core.js 里是 UTF-8 原文，本地 http.server 发 .js 不带 charset，这个浏览器按 windows-1252 解码；房间数据用 \u 转义所以没事，用户自己的 Chrome 也正常。build.py 现在给所有 <script src> 加 charset="utf-8"。

## 2026-10-01 交接要实时播放核，不能只靠 seek 比对
中国厅寒江：seek(i,1) 对 rest(i) 比出来 0.000，用户却看到交接时"突然放大、闪一下"——转场里把 DOM 装裱（frame mount）藏了，交接后引擎 0.6 s 才淡进来，一整圈装裱突然冒出。以后每处转场都要：停在上一厅 3 s → go(i)，在 t≈D 到进入停留后 1.5 s 之间每 ~120 ms 截一张，确认画心不跳、装裱不突然出现。装裱要么在转场画布里同步画出、随画一起到位，要么从头就别藏。

## 2026-10-01 Safari 会丢掉画到 canvas 的大图解码结果
夜宴→溪山在 Safari 里有十几次 0.2–1 s 顿挫：Safari 把 drawImage 过的大图解码结果几秒内丢掉，下次绘制在主线程重解码（大图 100–350 ms 一次），之前在小画布上"预热画一遍"没用。修法：上一厅停留时 img.decode() → createImageBitmap(img)（WebKit；Chrome 用 fetch→blob→createImageBitmap 在 worker 解码），播放时画位图，交接时 close；位图首次绘制会上传 GPU，出场前零点几秒先在不透明层下画 1 px。完全被遮住的层不画。修后 WebKit 最长帧 1003→98 ms。测 Safari 用 tools/wkprobe（系统 WebKit 真窗口），用户报"只有 Safari 卡"先查 `pmset -g | grep lowpowermode`。

## 2026-10-01 代理会陷进测试环境的问题里
两个代理（溪山性能、长卷查看器）功能早已做好，却花了两个多小时排查无头 Chrome 在 dpr 2 截图卡死、比对口径这类测试环境问题，还留下 19 个孤儿 Chrome 拖慢整台机器。总控要定期看 last_state.md 的更新时间：超过 ~40 分钟没更新、而活儿已经做完，就停掉流程自己收尾。无头 Chrome 截图卡死时改 dpr 1 或 --swiftshader。清孤儿时注意 zsh 不按换行拆分变量，`kill $P` 一个也杀不掉，用 `xargs kill < 文件`。
