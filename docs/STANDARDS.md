# 标准

**怎么用**：这些是对标的质量线，不是限制创作的规则清单。给创作 agent 的 brief 只写对标样板（说清好在哪）和用户明确否定过的底线（拼贴、橡皮式变形、斑块溶解/矩形分块、漂浮剪影、放大到糊、剧透、廉价装饰）；其余数值（时长、留白、缓动、节拍等）是默认值和参考，为想法服务时可以突破。验收时，客观项（事实、像素、衔接、性能、发布）照数值查；审美项交用户判断。

每条都是验收口径。来源：艺术的演进 18 厅的用户验收、`app/DESIGN-RULES.md`、`app/js/API.md`。为什么这样定，见 `LESSONS.md`。

## 1. 转场
**设计**
- 只做**一个发现**：两件作品之间本来就有的联系，或者新单元的核心手法作用在旧作品上。观众的感受应该是"原来它们是连着的"。
- 一句话说得清（写进 plan 的 `sentence`），有依据（`basis`，核查过）。
- 时长 ≤ 15 秒。节拍 4–5 个：静 → 铺垫 → 那一刻 → 沉淀 → 交接。那一刻前后要安静，给它留呼吸。
- 自然：整段只用一套连续的物理逻辑（光、天气、镜头、材料、墨、时间）。禁止：
  - 拼贴、贴上去的人物、漂浮的剪影；
  - 橡皮式的身体变形（"三个人变成三条船"）；
  - 斑块溶解、矩形分块显现、硬边；
  - 过早露出下一件作品，剧透了那一刻；
  - 用放大到糊的位图当画面。
- 全屏只在想法需要时用。规模只是手段。
- 方案由一个人定一个核心。多人发散可以，合成时不拼盘。
- 假说在画布字幕里也要留余地（"像……"、"有研究者认为"）。

**契约**（engine/app/js/API.md）
- `draw(p, ctx)` 是 p 的纯函数：可暂停、回放、任意 seek。
- p = 0 等于上一厅的停留画面，p = 1 等于本厅停留画面：作品区平均像素差 ≤ 1.0，dpr 1 和 dpr 2 都要测。整数设备像素对齐（encl 内框）。
- init() 和 rest() 要能独立工作：点时间线直接进厅不播转场。
- 阅读面板打开时 `ctx.tool='special'`，rest() 不在作品上画；`ctx.reading` 时不在 `ctx.readRect` 里画。
- 有停留附加物（地面、光束、雾）时，p = 1 就要画上，下一厅 p = 0 要接着画（`EH_SHARED.<id>Rest`）。
- 覆盖层用 `ctx.layer`；隐藏了控制条的，所有退出路径都要恢复。
- 交付：`_wip/sync/<id>.timeline.md`（每拍的秒数和 D）+ `rooms/<id>/t.done`。

**流畅**
- 1389×713、dpr 2：`EH.debug.cost(i,240)` p95 < 8 ms（修改后的目标 < 6 ms），max < 16 ms。
- `EH.debug.motion(i,60)`：没有意外的跳变，没有长时间的死帧。
- 实时回放（jump(i−1)，等 3–4 s，go(i)，每帧记 rAF 间隔）：墙钟 / 转场时长 ≈ 1.00；0.5 s 之后没有 > 100 ms 的帧，目标是没有 > 50 ms 的帧。还要测"进上一厅 1 秒就 go(i)"。
- 播放期间：不新建画布、不首次使用纹理/图案/滤镜、不 getImageData、不 drawImage 未解码的图、主线程单次阻塞 ≤ 50 ms、不等任何计算。

## 2. 特别展项
- **能玩**：像洛可可的秋千——有物理手感（惯性、阻尼、重量、吸附、压力），有反馈（声音、动作、结果），玩着玩着就懂了这件作品的想法。开关、图表、说明性动画不算。
- 原作始终是主角：展项让人体会作者的手法和想法，不替代原作，不让参观者的作品挂上墙。
- 先做窄屏、面板内版本，再做挂在作品上的覆盖版（按 `api.artRect()` 对齐）。可拖动画布加 `touch-action: pan-y`。
- 指针 + 触屏 + 键盘都能玩。空格、←、→、Esc 归引擎；展项用拖动、按住、按钮。
- 触控目标 ≥ 44×44 px；触屏设备的文案不写"悬停/点击/方向键"（`matchMedia('(hover:none)')`）。
- 文字从 `room.json` 的 `special.*` 读，带默认值；不写死在代码里。
- 声音走引擎的音频（`api.sfx`、房间音效），不自建 AudioContext：否则静音开关管不到，离开展厅也可能不停。
- 面板关闭时 `host._dispose` 清掉定时器、监听、循环声。
- 带 alpha 的图按透明处理：对比和查看器用墙色垫底，不用黑色。

## 3. 内容与排版（细则 = app/DESIGN-RULES.md）
**长度**（连标点计，交付前用脚本实测）
| 字段 | 上限 |
|---|---|
| 展厅名 zh | ≤ 5 字 |
| one（一句话简介） | ≤ 18 字，按，或；分句，每句 ≤ 12 字 |
| work | 120–180 |
| origin | 150–220 |
| traits ×4 | 每条 40–70 |
| note | ≤ 30 |
| chain | 80–120 |
| 引文出处 | ≤ 40 |

**中文排版**
- 段落 `line-break: strict` + `text-wrap: pretty`，标题 `text-wrap: balance`。
- 中文与数字/拉丁字母之间一个半角空格，渲染时 `nb()` 转不换行空格；内容里不手写 NBSP。
- ≤ 16 字的《作品名》、≤ 14 字的（括注）、≤ 8 字的"术语"整组不断行，紧跟的标点随组（`keep()` / `tx()`）。所有面向观众的文字经过 `tx()`。
- 引号用 “”，作品名用《》，不用「」。范围：1508–1512 年；端点带空格时写 ` – `。
- 竖排（中国艺术等）：`writing-mode: vertical-rl`，数字用汉字或直排组合（`text-combine-upright`），标点用竖排字形，避头尾同样适用。

**展签（art）**
- `who` 中文名，佚名放最前；`whoLat` 只写"姓名, 生卒"。
- `title` 《短名》+ 至多一个（括注），≤ 13 字；`short` 只有《短名》。
- `meta` 固定三行：年代 + 材质；尺寸或"尺寸不详"；城市，机构（编号）。
- `credit`：`<来源>, File:<名> — 摄影 <作者>，<许可>`；版权期内加 `— © <版权方>`。不加句号。
- `sources[]` 每条有面向观众的 `label`（发布方 · 标题）；核查推理写 factcheck.md。

**分工与措辞**
- 同一事实一个展厅只出现一次：展签 = 这是什么；work = 看到什么；origin = 历史；traits = 通性；special = 互动。
- 假说处处留余地，一句话简介和画布字幕也不例外。
- 宗教、民族、疆域等敏感内容：信仰说法写成"信徒相信 / 传统说法"，学术观点写成"学者认为"，有争议就并列并注明本展不作裁决（例：巴洛克"谁是马太"）。

**布局与可读性**
- 布局按实测推导，不写死常数；叠放文字用流式容器。文字间距 ≥ 12 px，文字与作品 ≥ 32 px，文字不压作品。
- 次级文字用 `--ink-2` / `--ink-3`（引擎按墙色算，对比 ≥ 7:1 / ≥ 4.6:1），不用透明度调暗。
- 字号：观众要读的 ≥ 12 px，展签 ≥ 13 px。激活状态不只靠颜色。
- 手机横屏（高 < 520）每个布局分支都要处理；作品宽度 < 视口 40% 算 bug。
- lint（`tools/layout_lint.mjs`）：overlap / onart / offscreen / overflow 必须为 0。日常只跑 1389×713；全尺寸矩阵（1389×713、1280×720、1920×1080、2560×1440、1024×768、390×844、375×667、844×390）在改了 core/index.html 或出现排版问题时跑。

## 4. 声音
- 每厅一首本时代/本文化的音乐，60–150 s 无缝循环（乐句处接、烘焙交叉淡化），−23 LUFS，MP3 128 kbps，≤ 2.5 MB，gain ≈ −8。默认 p = .62 淡入，可设 `musicAt`。
- 音效克制：那一刻之前安静，那一刻一个清楚的声音，其余少而轻。宁可少一个 cue。
- 声音贴合材料与年代，自然、不游戏化。宗教仪式的声音（诵经、宣礼、钟）只作环境与那一刻，不做花哨效果。
- 一次性音效峰值 ≈ −3 dBFS、≤ 200 KB；循环声 ≈ −28 LUFS、≤ 600 KB、无缝；44.1 kHz，除环境声外单声道；多做几个变体。用 ffmpeg（volumedetect / ebur128）实测。
- 分工：音效设计写 `audio/cues/<id>.json`（按 t.done 后的 timeline），转场代码不调 ctx.sfx；两处不做同一个声音。音效单文件交付，总控 `pack_sfx.py` 打包。
- 音乐任何时候都能做；音效素材可先做，时间表必须等 t.done。

## 5. 版权与署名
- 优先公有领域的高清原件（博物馆开放获取、Wikimedia Commons）。比例、颜色与馆方图比对，裁掉画框。原图存 `rooms/<id>/src/` + `SOURCE.txt`（网址、像素、日期、理由）。
- 著名的版权期内作品照样挂原作（非商用展示，用户接受风险）：credit 写明版权方，以馆方标注为准。
- 音乐要同时核实**作品**和**录音**的许可；CC BY 的署名由 build 汇总显示在阅读面板。
- credits 表格里链接一律写成 `[名称](url)`，裸网址会变成标题并被导出判为外部请求。
- 字体用开源许可（OFL 等）并自托管。
- 下载一律用通用浏览器 User-Agent；请求头、网址、文件里不放用户邮箱、姓名等个人信息。
- 用户不要单独的版权说明页；致谢总表放在尾声展项里。

## 6. 性能与浏览器
- 流畅度以**真实浏览器 dpr 2** 为准。无头 dpr 1 的结果只作参考。
- 应用内浏览器实测前先测空闲 rAF：≈ 16 ms 有效；≈ 1000 ms 说明面板不在屏幕上被限帧，数据作废。
- 引擎把 dt 限到 1/24 s：画不完的帧会变成慢动作，不是跳帧。所以重活必须离线。
- 所有图片、图案、滤镜、离屏画布在上一厅停留时分小任务预热（decode、画一次到小画布、按最终尺寸分配）。
- 每帧逐笔重绘这类重活 → 离线预渲染成 H.264 视频（mp4）播放。
- 不依赖 `CanvasRenderingContext2D.filter` 做关键效果（Safari 不支持，会被忽略）：灰度、模糊等要预渲染或逐像素离线算。黑白按线性亮度或 L* 算，不用 CSS grayscale。
- 换厅时释放大画布和 WebGL 上下文；长时间自动播放看内存。
- 0 个外部请求（大陆访问）：字体自托管、无 CDN、无地图瓦片服务、无统计脚本。路径全相对（镜像在子路径下）。单文件 < 25 MiB。
- 目标浏览器：桌面 Chrome（用户的视网膜 Mac）、Safari、手机 Chrome/Safari。
