# 展厅排版与布局规范

来自《艺术的演进》2026-09-25 首批四厅复盘：用户在 1389×713 的窗口里看到文字重叠、排版拥挤；随后四路审查又找出 57 条问题。
引擎已实现的部分（布局实测、nb()/tx()、颜色 token）对任何主题都生效；字数和展签结构是艺术展的口径，其他主题按同样的思路另定并写进本项目的这份文件。
做每个新展厅之前先读这份规范。交付前必须通过文末的检查。

## 1. 布局：一律按实测，不写死常数
- 作品悬挂区按周边元素的实测尺寸推出来：竖排标题栏的右边 → 悬挂区 → 展签栏 → 底部控制条。不要在两个地方各写一遍常数（core.js `areaFor`）。
- 叠在一起的文字块放进同一个流式容器（flex column + gap）。不要各自用 absolute 定位，那样一块变高就会压到另一块。
- 由内容决定的尺寸要按可用空间收缩。例如竖排标题的字号，按"窗口高度 − 说明块高度 − 间距"算（`fitTitles`）。
- 间距要求：
  - 文字与文字之间 ≥ 12 px。
  - 文字与画框之间 ≥ 32 px；任何布局下文字都不能压在作品上。
  - 查看器的说明、对比的标签，要么放在图像外面，要么预留实测高度。
- 每种布局分支都要有手机横屏（高 < 520）的处理。作品宽度 < 视口宽度的 40% 就算 bug。
- 叠在图像上的控件（查看器工具条、提示）要有底色。
- 可滚动的文字面板，上下边缘用渐隐遮罩，不能从字中间切开。

## 2. 中文排版
- 段落用 `line-break: strict` 和 `text-wrap: pretty`，标题用 `text-wrap: balance`。这些已写进 index.html，全局生效。
- 数字和单位不能断开：中文与数字、拉丁字母之间保留一个半角空格，渲染时由 core 的 `nb()` 转成不换行空格。内容里不要手写 NBSP。
- ≤ 16 字的《作品名》、≤ 14 字的（括注）、≤ 8 字的"术语"，整组不断行，后面紧跟的标点也跟着这一组（避头），由 core 的 `keep()` / `tx()` 处理。所有面向观众的文字都要经过 `tx()`。
- 一句话简介（`one`）：全句 ≤ 18 字，按逗号或分号分成子句，每个子句 ≤ 12 字，只在子句之间换行。
- 展厅名 ≤ 5 字。竖排标题每个字大约占 1.34 个字号的高度。
- 引号用 “”，作品名用《》，不用「」。
- 范围写法：
  - 纯数字不加空格：1508–1512 年、公元前 450–440 年。
  - 端点本身带空格或单位时，写成 ` – `：公元前 27 年 – 公元 68 年。
- 字数一律连标点一起计，交付前用脚本实测：
  - one ≤ 18、work 120–180、origin 150–220。
  - traits 每条 40–70、note ≤ 30、chain 80–120、引文出处 ≤ 40。
- 同一个事实在一个展厅里只出现一次：
  - 展签只负责"这是什么"，work 讲"看到什么"，origin 讲历史，traits 讲通性，special 讲互动。
- 假说在所有出现的地方都要留有余地（"有研究者认为"、"像……"），一句话简介和画布上的字幕也不例外。

## 3. 展签结构（art 字段）
- `who`：中文作者名，佚名放最前，括号里不写身份。`whoLat`：只写"姓名, 生卒"，不写地点。
- `title`：《短名》，最多加一个（括注），总长 ≤ 13 字；描述性的内容放进 meta。
- `short`：只有《短名》，用于对比工具和调色板，必须有。
- `meta`：固定三行：
  1. 年代 + 材质；
  2. 尺寸，或"尺寸不详"；
  3. 城市，机构（编号）。

  每行 ≤ 2 行宽。
- `credit`：统一格式 `Wikimedia Commons, File:<名> — 摄影 <作者>，<许可>`。不写制作备注，结尾不加句号。
- `sources[]`：每条都要有面向观众的 `label`（发布方 · 标题）。核查推理写在 factcheck.md，不放进 claim 的展示文字。

## 4. 颜色与可读性
- 次要、第三级文字一律用颜色 token（`--ink-2`、`--ink-3`），不用透明度调暗。core 会按每个展厅的实际墙色算出这两个颜色，保证对比度 ≥ 7:1 和 ≥ 4.6:1。中间调的墙色（例如 #A89E8E）用透明度调暗一定不达标。
- 按下、激活状态不能只靠颜色表达：用粗细变化加圆点标记。
- 字号下限：观众要读的文字 ≥ 12 px，展签 ≥ 13 px；墙面文字用 clamp() 随视口放大。
- 触控目标 ≥ 44×44 px，视觉上的细下划线可以保留，把 padding 加大即可。
- 触屏设备上的文案不写"悬停"、"点击"、"方向键"，用 `matchMedia('(hover:none)')` 切换说法。

## 5. 转场模块的停留动画（rest）与特别展项
- 阅读面板打开期间，作品归特别展项和工具使用：引擎会传 `ctx.tool='special'`，rest() 不能在作品上画任何东西。
  反面教训：艺术史展的洛可可厅，停留动画盖住了秋千展项。
- 导航规则：点时间线或按 ←/→ 直接跳到停留画面，不播转场，同时关掉自动播放。模块不能假设"进厅一定先播过转场"：init() 和 rest() 都要能独立工作。
- `ctx.tool` 为 era 或 special 时，rest() 不能在 `ctx.to.rect` 上画任何东西。
- `ctx.reading` 时，不能在 `ctx.readRect` 里画东西：地面线、光晕、投影都要避开文字栏。
- 窄屏阅读时作品被隐藏，core 不会调用 rest()。
- 带 alpha 的图（抠图、异形画板）处处按透明处理：
  - 调色板跳过透明像素；
  - 对比和查看器用墙色垫底，不用黑色；
  - 抠图在查看器里不加矩形阴影。
- 对比时作品要完整显示（contain）；两件作品比例相差很大时，不用 cover 去裁。
- 特别展项先设计窄屏、面板内的版本。可拖动的画布加 `touch-action: pan-y`。
- 共享的标记结构一改（例如 meta 改成 span），展签和查看器两处的样式要同一次改完。选择器尽量写直接子元素（`>`），避免误伤嵌套的 `.nw`。
- 隐藏了控制条的转场，所有退出路径都要能恢复控制条。core 在 enter() 里已经兜底。

## 6. 交付前检查（必过）
1. 用 `python3 build.py --out <名字>` 构建。每次改 index.html 之后都要重新构建：页面结构是构建时内联进去的。
2. 在下面每个尺寸跑 `node tools/cdp.mjs run local-<名字>.html tools/layout_lint.mjs --w W --h H [--mobile] --quiet`：
   - 桌面：1389×713、1280×720、1920×1080、2560×1440；
   - 平板：1024×768；
   - 手机（加 `--mobile`）：390×844、375×667、844×390。

   lint 覆盖停留、阅读、年代对比、特别展项、查看器五种状态。overlap / onart / offscreen / overflow 必须为 0；tight / orphan 要逐条看过。
3. 截图亲眼看：每个展厅的停留、阅读面板全程、查看器、对比、特别展项，以及转场的 8 个进度点。
4. 首尾衔接的数值检查：seek(i,1) 对 rest(i)、seek(i,0) 对 rest(i-1)，作品区域的平均像素差 ≈ 0。
